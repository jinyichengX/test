0 渲染全景

矢量渲染的本质，是把数学描述的路径（一连串 moveTo / lineTo）转换成离散的像素阵列。libcg 不是"连线然后对封闭区域洪水填充"——那只能得到硬边锯齿。它采用扫描线光栅化 + 有符号面积覆盖法，逐像素计算亚像素级覆盖率，从而得到平滑的抗锯齿边缘。

核心思想

每条 lineto 边缘按像素行/列切成小段，用有符号梯形面积累计每个像素的覆盖量。向上走的边 cover 为正、向下为负，累加即得 winding number（绕数），由此区分"内部/外部"。

最终渲染结果（抗锯齿灰度）— 后续阶段拆解其生成过程

1 路径存储 cg_path_t

用户调用 cg_move_to / cg_line_to 时，库并不会立刻画线，而是把指令记录下来。路径用两个并行数组存储：elements[] 记录指令类型（MOVE_TO=0 / LINE_TO=1 / CLOSE=3），points[] 记录坐标。moveTo 开新子路径；close 把 start 点追加到末尾形成闭合。

static void cg_path_line_to(cg_path_t* path, double x, double y) {
  cg_array_ensure(path->elements, 1);
  cg_array_ensure(path->points, 1);
  path->elements.data[path->elements.size] = CG_PATH_ELEMENT_LINE_TO; // =1
  path->elements.size += 1;
  path->points.data[path->points.size].x = x;
  path->points.data[path->points.size].y = y;
  path->points.size += 1;
}
为什么用两个数组？

elements 记录"做什么"，points 记录"在哪做"。curve_to 会消耗 3 个点，所以 points 的下标推进量随指令类型变化。这种"指令流 + 数据流"分离是矢量路径的标准表示。

指令逐条填入 elements[] + points[] 两个并行数组

2 定点化 浮点 → 26.6 → 8.8

光栅化要用整数面积计算覆盖率，避免浮点误差。坐标经过两次缩放：FT_COORD (×64 → 26.6 定点)，UPSCALE (×4 → 8.8 定点)。ONE_PIXEL=256，所以 8.8 定点下 1 像素 = 256 个单位。TRUNC 取像素整数坐标，FRACT 取像素内小数(0~255)。

// xft.c
#define PIXEL_BITS  8
#define ONE_PIXEL   (1L << PIXEL_BITS)   // =256
#define TRUNC(x)    (TCoord)((x) >> PIXEL_BITS)
#define FRACT(x)    (TCoord)((x) & (ONE_PIXEL-1))
#define UPSCALE(x)  ((x) * (ONE_PIXEL >> 6))  // *4
// cg.c
#define FT_COORD(x) (XCG_FT_Pos)((x) * 64)
为什么 8.8 而非 26.6？

面积 = 宽 × 高，两个 8.8 相乘得 16.16，需要足够位数承载。8 位小数给出 1/256 像素精度，足以产生 256 级灰度（即覆盖率 0~255）。

坐标 ×64→26.6 定点, ×4→8.8 定点。TRUNC 取像素整数, FRACT 取亚像素小数

3 Outline 轮廓 XCG_FT_Outline

路径在光栅化前被转换成 FreeType 风格的 outline——一个更紧凑、面向光栅化的结构。对纯 lineto 路径，所有点 tag 都是 ON(1)。contours[] 记录每个子路径最后一个点的下标，contours_flag[] 标记是否闭合。

static void ft_outline_line_to(XCG_FT_Outline* ft, double x, double y) {
  ft->points[ft->n_points].x = FT_COORD(x);   // *64
  ft->points[ft->n_points].y = FT_COORD(y);
  ft->tags[ft->n_points]   = XCG_FT_CURVE_TAG_ON; // =1
  ft->n_points++;
}
contours[] 的作用

它把一维点序列切成多个独立子路径。光栅化时按 contour 分组处理，每个子路径独立计算 winding。

Outline: points[] + tags[](ON=1) + contours[](子路径边界) + contours_flag[](闭合?)

4 按 Y 切行 gray_render_line ★核心

这是整个渲染器的灵魂。一条任意方向的线段，要被按 Y 轴的像素边界切成若干小段，每段恰好落在一个像素行（ey）内。切法用 Bresenham 式整数递推：从起点 fy1 到下一个像素边界距离 p=(256-fy1)*dx，除以 dy 得到这段的 x 增量 delta。

static void gray_render_line(RAS_ARG_ TPos to_x, TPos to_y) {
  TCoord ey1=TRUNC(ras.y), ey2=TRUNC(to_y);
  if(ey1==ey2){ gray_render_scanline(ey1,ras.x,fy1,to_x,fy2); return; }
  // dy>0: p=(256-fy1)*dx, first=256, incr=1
  XCG_FT_DIV_MOD(TCoord, p, dy, delta, mod);
  x = ras.x + delta;
  gray_render_scanline(ey1, ras.x, fy1, x, first);  // 首段
  ey1 += incr;
  while(ey1 != ey2) {                              // 中间整像素行
    XCG_FT_DIV_MOD(..., lift, rem);
    x2 = x + lift + (mod补偿);
    gray_render_scanline(ey1, x, 256-first, x2, first);
    ey1 += incr;
  }
  gray_render_scanline(ey1, x, 256-first, to_x, fy2); // 末段
}
关键洞察

线段被切成的每一段，其 y 跨度恰好是"从一个像素行内某小数位置到边界"或"整行"。这样每段都能在 render_scanline 中用梯形面积公式精确计算覆盖。

每条 lineTo 按 Y 像素边界切成多段, 每段落在一个像素行(ey)内

5 按 X 切格 · 面积累积 gray_render_scanline

每段（落在一个像素行 ey 内）再被按 X 像素边界切成更小的片段。对当前像素的 cell 累积两个量：area += (fx1+fx2)*dy（有符号梯形面积），cover += dy（有符号垂直覆盖量）。(fx1+fx2)*dy 就是梯形面积：fx1、fx2 是片段起止的 x 小数，dy 是 y 跨度。

static void gray_render_scanline(RAS_ARG_ TCoord ey, TPos x1,TCoord y1, TPos x2,TCoord y2){
  TCoord ex1=TRUNC(x1), ex2=TRUNC(x2);
  if(ex1==ex2){                       // 同一像素列内
    ras.area += (TArea)(fx1+fx2)*dy;  ras.cover += dy; return;
  }
  // 跨列：首段(到右边界) → 中间满宽段 → 末段(从左边界)
  ras.area += (fx1+256)*delta;  ras.cover += delta;  // 首段
  while(ex1!=ex2){                                          // 中间满宽
    ras.area += 256*lift;  ras.cover += lift;
  }
  ras.area += (fx1+fx2)*dy;  ras.cover += dy;               // 末段
}
有符号是精髓

向上走的边 dy>0，cover 为正；向下走的边 dy<0，cover 为负。同一像素列上正负 cover 累加就是绕数 winding，直接决定该像素是否在"内部"。area 的符号同步记录覆盖方向。

单像素行内按 X 切格: area+=(fx1+fx2)*dy (梯形面积), cover+=dy. dy>0↑正, dy<0↓负

6 Cell 覆盖表

经过阶段 4-5，所有边缘片段已被记录到一张稀疏的 cell 表。每个被路径触及的像素对应一个 cell，记录 area（有符号面积之和）和 cover（有符号覆盖次数/绕数贡献）。cells 按像素行组织成链表，同一行内按 x 排序。

typedef struct TCell_ {
  TCoord  x;        // 像素列
  TArea   area;    // 有符号面积 (梯形累积)
  TCoord  cover;   // 有符号覆盖次数
  PCell   next;    // 同行下一 cell
} TCell;
注意 area 是 2 倍面积

梯形面积公式 (fx1+fx2)*dy 对三角形给出的是底×高=2倍三角形面积。统一用 2 倍可避免除法。最终 coverage = |area| / 512 归一化到 0~255。

绿色=cover正(↑边), 红色=cover负(↓边). 深浅=|area|. 每个被路径触及的像素一格

7 Sweep 扫描 · 算覆盖率

所有边缘已就位，现在逐行从左到右扫描 cell 链表，把 area/cover 转成每个像素的最终覆盖率 coverage (0~255)。两步：① 满覆盖段——两个 cell 之间若 winding≠0，说明完全在内部，coverage=255；② 部分覆盖像素——area = cover*512 − cell.area，再 >>9 归一化。

static void gray_sweep(RAS_ARG) {
  for(int y=..; y<ycount; y++){
    TCoord cover = 0;          // 累积绕数 winding
    for(cell=ycells[y]; cell; cell=cell->next){
      if(cell->x > x && cover!=0)
        gray_hline(x,y, cover*512, gap);  // 满覆盖段
      cover += cell->cover;
      area = cover*512 - cell->area;
      gray_hline(cell->x, y, area, 1);     // 部分覆盖
    }
  }
}
绕数决定内外

cover 累积为 0 表示该区域在路径外（正负边抵消）；非 0 表示在内。non-zero 规则下 |cover|≥1 即满覆盖；even-odd 规则下取 cover 奇偶性。

Sweep: 逐行从左到右扫描 cell, cover 累积=winding, area=cover*512-cell.area, coverage=|area|>>9

8 填充规则与合成

最后一步：coverage 作为 alpha，结合填充规则和合成算子，把颜色写入像素缓冲。每个 span = {x, y, len, coverage}，即"在 y 行从 x 起连续 len 个像素、coverage 覆盖率"。合成时把源色按 coverage 混合到目标像素：r = src*ca + dst*(1-ca)。

coverage = (area >> 9);
if(coverage < 0) coverage = -coverage;
if(EVEN_ODD){ coverage &= 511; if(coverage>256) coverage=512-coverage; }
else{ if(coverage>=256) coverage=255; }
规则判据效果
non-zero|winding| ≥ 1 即内部同向叠加更实
even-oddwinding 为奇数即内部叠加区域变空洞
当前规则与对比规则下的最终渲染结果 · coverage 作 alpha → source_over 合成

9 Stroke 描边概览

Fill 是对路径内部填色，Stroke 是沿路径中心线向两侧加宽出一条"带子"再填充。libcg 的 stroke 不是直接画粗线——它把原始路径转换成一个加宽后的封闭 outline，然后对这个新 outline 执行与 fill 完全相同的光栅化流程。

步骤源码位置作用

2cg.c L911 · XCG_FT_Stroker_Set设置 width/cap/join/miter_limit
3xft.c · Stroker_ParseOutline遍历每条线段，法线偏移生成两条 border
4xft.c · ft_stroker_cap路径端点加 cap（butt/round/square）
5xft.c · ft_stroker_process_corner拐角处处理 join（miter/round/bevel）
6xft.c · Stroker_Export导出加宽 outline（两条 border 合并）
7xft.c · gray_raster对加宽 outline 执行 fill 光栅化
// cg.c L887-949 核心流程
if(stroke){
  ft_outline_convert(&outline, ctx, path, m);     // 原始路径→outline
  ftWidth = stroke->width * scale * 0.5 * (1<<6);  // radius (26.6)
  XCG_FT_Stroker_Set(stroker, ftWidth, ftCap, ftJoin, ftMiterLimit);

}
Stroke 的本质

Stroke = 生成加宽 outline + Fill。所以 fill 的 9 个阶段完全适用于 stroke——只是被光栅化的路径变成了加宽后的封闭多边形。

中心线（橙色）→ 加宽 outline（蓝色封闭多边形）→ 光栅化填充结果

10 中心线 + 法线偏移

Stroker 的核心操作：对每条线段计算法线向量（垂直于线段方向），然后将中心线两端沿法线方向偏移 ±radius（线宽的一半），得到两条平行偏移线——即 border A（+法线方向）和 border B（−法线方向）。

// xft.c XCG_FT_Stroker_LineTo (L2252)
delta.x = to->x - stroker->center.x;
delta.y = to->y - stroker->center.y;
line_length = XCG_FT_Vector_Length(&delta);
angle = XCG_FT_Atan2(delta.x, delta.y);
XCG_FT_Vector_From_Polar(&delta, stroker->radius, angle + XCG_FT_ANGLE_PI2); // 法线=方向+90°
// border[0] (left): point = to + delta
// border[1] (right): point = to - delta

法线 = 方向向量旋转 90°。对于方向 (dx,dy)，法线为 (−dy,dx)/len。偏移点 = 顶点 ± 法线 × radius。

两条 border 的含义

对于 CCW（逆时针）路径，border A 是外环、border B 是内环。闭合后两个轮廓一起填充，non-zero 规则自动填充两环之间的区域——即"带子"。

橙色=中心线, 蓝色=法线方向, 绿色=border A (+法线), 青色=border B (−法线)

11 Line Cap 线帽

开放路径的端点需要"封口"。libcg 支持三种 cap，由 ft_stroker_cap (xft.c L2029) 实现：

Cap形状实现
butt平口，垂直于线段方向直接连接 border A/B 端点
square方形，向外延伸 radius沿方向延伸 r，再连接
round半圆以端点为圆心画半圆弧
static XCG_FT_Error ft_stroker_cap(stroker, angle, side) {
  if(stroker->line_cap == ROUND){
    stroker->angle_in = angle;
    stroker->angle_out = angle + PI;
    ft_stroker_arcto(stroker, side);     // 半圆弧
  } else {
    // butt 或 square
    XCG_FT_Vector_From_Polar(&middle, radius, angle);
    if(cap == SQUARE) { middle += center; }  // square 延伸
    else { middle = center; }                 // butt 不延伸
    ft_stroke_border_lineto(border, &delta); // 连接到偏移点
  }
}
round cap 用 lineto 近似

源码中 round cap 通过 ft_stroker_arcto 用贝塞尔曲线近似圆弧。本工具直接用多段 lineto 近似——这正是"仅限 lineto"约束下的实现方式。

三种 cap 对比: butt(平口) / square(方形延伸) / round(半圆)

13 加宽 Outline 组装

所有偏移点、cap、join 处理完毕后，XCG_FT_Stroker_Export (xft.c L2721) 把两条 border 导出为一个新的 outline 结构：border A 正序 + border B 逆序（开放路径）或两个独立闭合轮廓（闭合路径）。这个新 outline 随后被送入标准 fill 光栅化器。

void XCG_FT_Stroker_Export(stroker, outline) {
  XCG_FT_Stroker_ExportBorder(stroker, BORDER_LEFT, outline);
  XCG_FT_Stroker_ExportBorder(stroker, BORDER_RIGHT, outline);
}
// 每条 border 通过 ft_stroke_border_close 闭合
// 闭合时 reverse=TRUE 会反转点序，使外环 CW、内环 CCW
闭合路径 vs 开放路径

闭合路径：两条 border 各自闭合，形成外环和内环。non-zero 填充规则自动填充两环之间。
开放路径：border A 正序 + end cap + border B 逆序 + start cap，合成一个封闭轮廓。

完整加宽 outline: 橙色中心线 + 绿色 border A + 青色 border B + cap/join 点

14 描边最终结果

加宽 outline 送入标准 fill 光栅化器后，经历与 fill 完全相同的流程：render_line 切行 → render_scanline 累积 area/cover → sweep 算 coverage → 合成。区别仅在于被光栅化的路径从"原始路径"变成了"加宽后的封闭多边形"。
