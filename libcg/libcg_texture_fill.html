全貌：一个纹理像素最终落到目标，中间经过哪些环节

从 RLE 生成之后，到图片像素写进目标表面，整条链路是什么？

先建立整体地图，避免一头扎进细节。libcg 的填充入口是 cg_fill() → cg_blend()，它按 paint 类型分派；类型是 TEXTURE 时进入 cg_blend_texture()。我们这次只关心 texture 这一支。

cg_fill(ctx)用户调用填充
▼
cg_blend(ctx, rle)按 paint.type 分派：COLOR / GRADIENT / TEXTURE
▼ paint.type == CG_PAINT_TYPE_TEXTURE
cg_blend_texture(ctx, rle, texture)本次主角，cg.c:2096

一句话总纲：形状先被光栅化成 RLE（一组带 AA 覆盖度的水平段），填充时对每个段里的每个目标像素，用「目标→纹理」的反向矩阵算出它该采样纹理的哪个像素，近邻取整拿到 RGBA，再乘上该像素的 coverage，最后按 operator 与目标已画内容混合。

起点：RLE 就是「形状的覆盖图」

mask(rle) 到底是什么数据结构？spans 里的 coverage 是什么含义？

光栅化阶段（FreeType 风格的 XCG_FT_Raster_Render）会回调一个函数，把每一行扫描得到的「水平连续、覆盖度相同」的像素段交给我们。这个回调就是 generation_callback，它把这些段原样塞进 rle->spans 数组。

cg.c:844-851 generation_callback
static void generation_callback(int count, const XCG_FT_Span * spans, void * user)
{
	struct cg_rle_t * rle = user;
	cg_array_ensure(rle->spans, count);
	struct cg_span_t * data = rle->spans.data + rle->spans.size;
	memcpy(data, spans, (size_t)count * sizeof(struct cg_span_t));
	rle->spans.size += count;
}

两个结构体的定义（cg.h）：

cg.h:144-161 struct cg_span_t / cg_rle_t
struct cg_span_t {
	int x;                  // 段起点的列坐标（目标像素空间）
	int len;                // 段的水平长度（像素个数）
	int y;                  // 段所在行
	unsigned char coverage; // 0-255 的抗锯齿覆盖度
};

struct cg_rle_t {
	struct { struct cg_span_t * data; int size; int capacity; } spans;
	int x, y, w, h;         // 所有 span 的并集包围盒（rasterize 后算出）
};

字段逐个解释：

字段含义实验台对应
x这一段从哪一列开始sp.x
len这一段横跨多少个像素sp.len
y这一段在哪一行sp.y
coverage0~255 的 AA 覆盖，255=完全在形状内，中间值=边缘sp.cov
x/y/w/h整组 span 的最小外接矩形（并集包围盒）maskCap 里的包围盒
为什么叫「RLE」（Run-Length Encoding）
一整行像素被压成「x + len + coverage」的段，而不是一个像素一条记录。同一行里 coverage 相同的连续像素合并成一条 span，所以形状内部的大块实心区只有很少几条 span，边缘 AA 区才是一条条细碎的小段。这就是 RLE 压缩的含义。

光栅化结束后，cg_rle_rasterize 末尾会从这些 span 反推包围盒（cg.c:982-998）：x 取所有 span 的 x 最小值，w 取「x+len」最大值减 x，y/h 取首末 span 的行号。这个包围盒就是后面判断图片是否越界、需要画多大范围的基础。

记住：RLE 只告诉我们「形状盖住了哪些像素、每个像素盖得多满（coverage）」。它完全不知道图片、不知道颜色——图片是下一阶段才被采样进来「填」进这些像素的。这就是「为什么图片会出现在 mask 里」的第一层答案：mask 定义了 哪些像素要画，图片定义了 这些像素填什么颜色。

纹理本身：cg_texture_t 结构体装了什么

填充时拿到的 texture 对象里，有哪几个字段在起作用？

用户通过 cg_set_source_surface() 或 cg_set_texture() 把一张 cg_surface_t（图片）设成当前 paint。它被包进一个 cg_texture_t。

};

	surface = cg_surface_reference(surface);
	cg_surface_destroy(texture->surface);

	texture->surface = surface;

字段默认值作用

核心语义：texture->matrix 是「纹理 → 目标」的正向映射

为什么图片会出现在那个位置？x、y 参数到底钉住了图片的哪个点？

这是回答你核心疑问最关键的一节。cg_set_source_surface(ctx, surface, x, y) 的实现极其简单，只有三行：

cg.c:2286-2291 cg_set_source_surface
struct cg_texture_t * cg_set_source_surface(struct cg_ctx_t * ctx, struct cg_surface_t * surface, double x, double y)
{
	struct cg_texture_t * texture = cg_set_texture(ctx, surface, CG_TEXTURE_TYPE_PLAIN);
	cg_matrix_init_translate(&texture->matrix, x, y);
	return texture;
}
cg.c:78-83 cg_matrix_init_translate
void cg_matrix_init_translate(struct cg_matrix_t * m, double tx, double ty)
{
	m->a = 1;   m->b = 0;
	m->c = 0;   m->d = 1;
	m->tx = tx; m->ty = ty;
}

所以 cg_set_source_surface(ctx, surf, x, y) 的语义是：把纹理像素 (0,0) 钉到目标坐标 (x, y)，其余像素按图片本身尺寸向右、向下铺开（先不考虑缩放旋转）。也就是说 x、y 是图片左上角在目标空间里的位置。

纹理像素 (0,0) ──forward──▶ 目标 (tx, ty) = (x, y)
纹理像素 (u,v) ──forward──▶ 目标 (x + u, y + v) （无缩放旋转时）
为什么叫「正向」映射
matrix 描述的是「从纹理坐标系出发 → 到目标坐标系」的方向（forward）。但采样时我们手上拿的是目标像素坐标，想知道的是「这个目标像素该显示纹理的哪个像素」，方向正好相反。所以后面必须先 invert（§7），把正向矩阵翻成反向矩阵再用。
一句话回答「图片为什么在那个位置」：是 cg_set_source_surface(x, y) 把 texture->matrix 初始化成「平移 (x,y)」，于是纹理 (0,0) 被映射到目标 (x,y)；采样时再反算回来，落在 mask 内部的目标像素就去纹理的对应位置取色。x、y 变了，图片整体就跟着平移，这就是位置由来的代码依据。

矩阵约定：行向量（row-vector）

libcg 的矩阵是列向量还是行向量？map_point 到底怎么算？

这决定了后面所有矩阵运算的写法，必须先说清楚。libcg 用的是行向量约定：点 p1 左乘矩阵 M。

cg.c:202-206 cg_matrix_map_point
void cg_matrix_map_point(struct cg_matrix_t * m, struct cg_point_t * p1, struct cg_point_t * p2)
{
	p2->x = p1->x * m->a + p1->y * m->c + m->tx;
	p2->y = p1->x * m->b + p1->y * m->d + m->ty;
}
┌ a b 0 ┐
(x1,y1,1) · │ c d 0 │ = (x1·a + y1·c + tx, x1·b + y1·d + ty, 1)
└ tx ty 1 ┘

x2 = x1·a + y1·c + tx y2 = x1·b + y1·d + ty

注意 b、c 的位置：b 是「x 对 y 的贡献」（切变/旋转），c 是「y 对 x 的贡献」。所以纯旋转矩阵长这样（cg.c:92-100）：

旋转角 θ： a=cosθ, b=sinθ, c=-sinθ, d=cosθ
缩放： a=sx, b=0, c=0, d=sy
平移： a=1, b=0, c=0, d=1, tx=tx, ty=ty
实验台里的矩阵对象
页面 JS 里矩阵同样用 {a,b,c,d,tx,ty} 六个字段，mapPoint(m,x,y) 的公式与 cg_matrix_map_point 一字不差。你可以在实验台悬停时看到 forward 与 inverse 两组矩阵的实时数值。

合成矩阵：cg_matrix_multiply 把 CTM 叠上去

为什么填充时要把 texture->matrix 再乘一个 state->matrix？

texture->matrix 只描述「纹理 → 用户空间」。但目标表面可能还套了一层 CTM（current transformation matrix，即 state->matrix，描述「用户空间 → 设备/目标空间」）。要把纹理直接映射到目标，需要把两者合成。

cg.c:135-155 cg_matrix_multiply（m = m1 × m2）
void cg_matrix_multiply(struct cg_matrix_t * m, struct cg_matrix_t * m1, struct cg_matrix_t * m2)
{
	struct cg_matrix_t t;
	t.a = m1->a * m2->a;
	t.b = 0.0;
	t.c = 0.0;
	t.d = m1->d * m2->d;
	t.tx = m1->tx * m2->a + m2->tx;
	t.ty = m1->ty * m2->d + m2->ty;
	if(m1->b != 0.0 || m1->c != 0.0 || m2->b != 0.0 || m2->c != 0.0)
	{
		t.a += m1->b * m2->c;
		t.b += m1->a * m2->b + m1->b * m2->d;
		t.c += m1->c * m2->a + m1->d * m2->c;
		t.d += m1->c * m2->b;
		t.tx += m1->ty * m2->c;
		t.ty += m1->tx * m2->b;
	}
	memcpy(m, &t, sizeof(struct cg_matrix_t));
}

在 cg_blend_texture 里它是这样被调用的（cg.c:2107-2109）：

cg.c:2107-2109 cg_blend_texture 内
data.matrix = texture->matrix;                              // 1. 纹理→用户
cg_matrix_multiply(&data.matrix, &data.matrix, &state->matrix); // 2. 再乘 用户→目标
cg_matrix_invert(&data.matrix);                            // 3. 求逆 → 目标→纹理
注意 multiply 的快速路径
当 m1、m2 都无切变/旋转（b=c=0）时，它只算对角项与平移项，省掉一堆乘加。这正是「先看有没有 b/c」分支存在的意义——大多数纯平移/缩放场景都能走这条快路。
实验台对应：页面默认把 state->matrix 当作 identity（即用户空间 == 目标空间），所以 texture->matrix 乘以 identity 不变。你在实验台里调的 scale / rotate / tx / ty 就是直接捏 texture->matrix 本身——等价于 CTM 为单位矩阵时的完整流程。

反转：cg_matrix_invert 得到「目标 → 纹理」

为什么不直接用正向矩阵算，非要 invert？invert 之后是什么样？

因为采样是逆向的：正向矩阵把「纹理坐标 → 目标坐标」，但渲染循环里我们遍历的是目标像素（span 的 x、y 就在目标空间），要反过来问「这个目标像素来自纹理的哪里」。所以对合成后的矩阵求逆。

cg.c:157-200 cg_matrix_invert
void cg_matrix_invert(struct cg_matrix_t * m)
{
	double a, b, c, d, tx, ty, det;
	if((m->c == 0.0) && (m->b == 0.0))       // 纯平移/缩放（无切变旋转）
	{
		m->tx = -m->tx;
		m->ty = -m->ty;
		if(m->a != 1.0) { if(m->a == 0.0) return; m->a = 1.0/m->a; m->tx *= m->a; }
		if(m->d != 1.0) { if(m->d == 0.0) return; m->d = 1.0/m->d; m->ty *= m->d; }
	}
	else
	{
		det = m->a * m->d - m->b * m->c;
		if(det != 0.0)
		{
			a = m->a; b = m->b; c = m->c; d = m->d; tx = m->tx; ty = m->ty;
			m->a = d / det;   m->b = -b / det;
			m->c = -c / det;  m->d = a / det;
			m->tx = (c * ty - d * tx) / det;
			m->ty = (b * tx - a * ty) / det;
		}
	}
}
纯平移时 invert 会变成什么
若正向矩阵只有平移（a=1,d=1,b=c=0, tx, ty），求逆后是 a=1,d=1,b=c=0, tx=-tx, ty=-ty。于是「目标 (x,y) → 纹理 (x - tx, y - ty)」——目标像素减去图片左上角坐标，就得到它在图片里的坐标。这就是实验台里默认 tx=0 时「目标 (110,110) → 纹理 (110,110)」的直接来源。
实验台对应：invert(m) 与 cg_matrix_invert 走同一套公式（2×2 伴随矩阵除以行列式，再解平移项）。悬停时 trace 面板会同时打印 forward 和 inverse 两行矩阵，你能直接看到「正向平移 (tx,ty)」如何变成「反向平移 (-tx,-ty)」。

分派：cg_blend_texture 的 4 条采样路径

invert 之后，代码怎么决定走哪条采样函数？

准备好采样矩阵后，cg_blend_texture 用一个双重判断把它派发到四条路径之一。先看完整代码：

cg.c:2096-2126 cg_blend_texture（完整）
static inline void cg_blend_texture(struct cg_ctx_t * ctx, struct cg_rle_t * rle, struct cg_texture_t * texture)
{
	if(texture)
	{
		struct cg_state_t * state = ctx->state;
		struct cg_texture_data_t data;
		data.width = texture->surface->width;
		data.height = texture->surface->height;
		data.stride = texture->surface->stride;
		data.alpha = (int)(state->opacity * texture->opacity * 256.0);
		data.pixels = texture->surface->pixels;
		data.matrix = texture->matrix;
		cg_matrix_multiply(&data.matrix, &data.matrix, &state->matrix);
		cg_matrix_invert(&data.matrix);
		struct cg_matrix_t * m = &data.matrix;
		if((m->a == 1.0) && (m->b == 0.0) && (m->c == 0.0) && (m->d == 1.0))
		{
			if(texture->type == CG_TEXTURE_TYPE_PLAIN)
				blend_untransformed_argb(...);      // 路径 A
			else
				blend_untransformed_tiled_argb(...); // 路径 C
		}
		else
		{
			if(texture->type == CG_TEXTURE_TYPE_PLAIN)
				blend_transformed_argb(...);        // 路径 B
			else
				blend_transformed_tiled_argb(...);   // 路径 D
		}
	}
}

两个判断维度：

判断条件含义
invert 后 a==1 且 b==c==0 且 d==1反向矩阵只剩纯平移（无缩放/旋转/切变），采样 = 整数平移
texture->type == PLAIN 或 TILED越界时「透明跳过」还是「取模平铺」
invert 后 只剩平移？
是 → 走 untransformed，否 → 走 transformed
type == ?
PLAIN → 越界透明　TILED → 取模平铺
A blend_untransformed_argb
（平移 + 透明）
C blend_untransformed_tiled_argb
（平移 + 平铺）
B blend_transformed_argb
（变换 + 透明）
D blend_transformed_tiled_argb
（变换 + 平铺）
为什么要有「untransformed」这条捷径
纯平移是最常见的情况（用户只调 cg_set_source_surface(x,y)，不旋转缩放）。此时目标像素到纹理像素只是整数加减，不需要 16.16 定点、不需要逐像素重算，可以整段（span）一次性 memcpy 式地搬。transform 路径则必须逐像素走定点累加，慢得多。分派的意义就是「快的场景走快的路」。
实验台对应：trace 面板顶部实时显示当前分派结果。你把 scale=1、rotate=0 时会看到「untransformed」，一旦调 scale 或 rotate 就自动切到「transformed」；切 type 则在 PLAIN/TILED 之间切换。和 C 代码的双重 if 完全一致。

路径 A：blend_untransformed_argb（PLAIN + 纯平移）

默认 set_source_surface(x,y) 的场景，代码怎么把图片搬进 mask？

这是最常用的一条路：invert 后只剩平移，类型是 PLAIN。此时反向矩阵就是 (tx, ty)（其实是 -x, -y），采样坐标 = 目标像素坐标 + 固定偏移。

cg.c:1812-1848 blend_untransformed_argb
static inline void blend_untransformed_argb(..., struct cg_texture_data_t * texture)
{
	cg_comp_function_t func = cg_comp_map[op];
	int image_width = texture->width;
	int image_height = texture->height;
	int xoff = (int)(texture->matrix.tx);   // 反向平移量（= -x）
	int yoff = (int)(texture->matrix.ty);   // 反向平移量（= -y）
	int count = rle->spans.size;
	struct cg_span_t * spans = rle->spans.data;
	while(count--)
	{
		int x = spans->x;
		int length = spans->len;
		int sx = xoff + x;              // 该 span 起点在纹理里的列
		int sy = yoff + spans->y;        // 该 span 在纹理里的行
		if(sy >= 0 && sy < image_height && sx < image_width)
		{
			if(sx < 0) { x -= sx; length += sx; sx = 0; }  // 左越界裁剪
			if(sx + length > image_width)
				length = image_width - sx;                        // 右越界裁剪
			if(length > 0)
			{
				int coverage = (spans->coverage * texture->alpha) >> 8;
				uint32_t * src = (uint32_t *)(texture->pixels + sy * texture->stride) + sx;
				uint32_t * dst = (uint32_t *)(surface->pixels + spans->y * surface->stride) + x;
				func(dst, length, src, coverage);
			}
		}
		++spans;
	}
}

逐行拆解关键点：

代码做了什么
xoff = matrix.tx反向矩阵的平移量，正好是「目标坐标 → 纹理坐标」的固定偏移
sx = xoff + x这条 span 起点在纹理里的列号
sy 越界判断行在图片高度外 → 整条 span 直接跳过（PLAIN 的「图外透明」）
sx<0 裁剪span 左边伸到图片左边外侧，把起点右移到 0 并缩短长度
sx+len 裁剪span 右边超过图片右边，长度截到图片边界
coverage>>8AA 覆盖 × 整体 alpha，见 §12
func(dst, len, src, cov)把整段纹理像素按 operator 合成进目标
为什么这里能「整段搬」
因为纯平移下，一行里的每个目标像素对应纹理里连续的一段像素（sx, sx+1, sx+2 …），所以可以一次性取 src 指针 + length，交给合成函数整段处理，效率最高。这也是分派到「untransformed」的真正价值。

路径 B：blend_transformed_argb（PLAIN + 缩放/旋转）

一旦缩放或旋转，逐像素采样是怎么用 16.16 定点算的？

当反向矩阵含缩放/旋转时，目标一行像素对应的纹理坐标不再等距连续，必须逐像素算。libcg 用 16.16 定点（FIXED_SCALE = 1<<16）累加，避免每像素做一次浮点乘。

cg.c:1811 FIXED_SCALE 定义
#define FIXED_SCALE (1 << 16)   // 65536，即 16.16 定点
cg.c:1850-1898 blend_transformed_argb
static inline void blend_transformed_argb(..., struct cg_texture_data_t * texture)
{
	cg_comp_function_t func = cg_comp_map[op];
	uint32_t buffer[1024];
	int image_width = texture->width, image_height = texture->height;
	int fdx = (int)(texture->matrix.a * FIXED_SCALE);  // 每右移 1 像素，纹理 x 的定点增量
	int fdy = (int)(texture->matrix.b * FIXED_SCALE);  // 每右移 1 像素，纹理 y 的定点增量
	int count = rle->spans.size;
	struct cg_span_t * spans = rle->spans.data;
	while(count--)
	{
		uint32_t * target = (uint32_t *)(surface->pixels + spans->y * surface->stride) + spans->x;
		double cx = spans->x + 0.5;   // ★ 像素中心，不是左上角
		double cy = spans->y + 0.5;
		int x = (int)((texture->matrix.c * cy + texture->matrix.a * cx + texture->matrix.tx) * FIXED_SCALE);
		int y = (int)((texture->matrix.d * cy + texture->matrix.b * cx + texture->matrix.ty) * FIXED_SCALE);
		int length = spans->len;
		int coverage = (spans->coverage * texture->alpha) >> 8;
		while(length)
		{
			int l = CG_MIN(length, 1024);
			uint32_t * end = buffer + l;
			uint32_t * b = buffer;
			int start = 0, clen = 0;
			while(b < end)
			{
				int px = x >> 16;   // 定点 → 整数（近邻，向下取整）
				int py = y >> 16;
				if(((unsigned int)px < (unsigned int)image_width) &&
				    ((unsigned int)py < (unsigned int)image_height))
				{
					*b = ((uint32_t *)(texture->pixels + py * texture->stride))[px];
					clen++;
				}
				x += fdx;  y += fdy;   // 定点累加，走向下一像素
				++b;
				if(clen == 0) start++;
			}
			func(target + start, clen, buffer + start, coverage);
			target += l;  length -= l;
		}
		++spans;
	}
}

关键点逐个说：

代码含义
cx = x + 0.5★ 采样的是像素中心，不是左上角。这样旋转/缩放时纹理对齐更自然（避免偏移半像素）
x = (c·cy + a·cx + tx)·65536就是 map_point 的行向量公式，乘 65536 转成 16.16 定点
fdx = a·65536目标向右走 1 像素，纹理 x 的定点增量；循环里累加避免重复乘
px = x >> 16定点除以 65536，向下取整 → 近邻采样（无插值）
bounds 检查越界的像素被跳过（PLAIN 图外透明），且用 start/clen 把连续的有效段聚拢
1024 缓冲一次最多算 1024 像素进 buffer，再整段交给合成函数
「近邻采样」意味着什么
px = x >> 16 就是 floor(纹理x / 65536)，等价于 JS 里的 Math.floor()。它不做双线性插值，放大时会出现明显马赛克；这是 libcg 为嵌入式性能做的取舍。实验台里 sample() 用 Math.floor 与之一致。

路径 C/D：TILED 取模平铺

type=TILED 时，越界的像素坐标怎么「回绕」到图片里？

PLAIN 在越界时是「透明跳过」，TILED 则把越界坐标取模回绕，让图片像墙纸一样无限重复。两条 tiled 路径分别对应「纯平移」和「变换」两种前提。

cg.c:1900-1939 blend_untransformed_tiled_argb（纯平移 + 平铺）

	}

{
	if(px16 < 0) px16 += image_width << 16;   // 负定点归一

	int py = py16 >> 16;
	*b = image_bits[py * scanline_offset + px];   // 取模后再近邻采样

	py16 += py_delta;
	if(py16 >= image_height << 16) py16 -= image_height << 16;
	++b;
}
纯平移 vs 变换，回绕的差别
纯平移时（路径 C），回绕单位是整数像素（% image_width），并且一行 span 最多被右边界切成若干段、每段从图片左端重新开始。变换时（路径 D），坐标是 16.16 定点，所以回绕单位是 image_width << 16，先对定点取模再右移 16 位取整——保证旋转放大后依然正确平铺。
实验台对应：sample() 的 TILED 分支用 ((px % TEX)+TEX)%TEX 做正数归一取模，与 C 的「先 % 再负值加回」等价。你在实验台把 type 切成 TILED、把 tx/ty 调大或调成负数，就能看到图片无限重复且方向正确的效果。

覆盖度：coverage 与整体 alpha 的合成

AA 的 coverage、state->opacity、texture->opacity 是怎么合并成一个 alpha 的？

每个采样函数里都有一行几乎相同的代码：

cg.c:1840 / 1869 / 1924 / 1961 四条路径里的 coverage 计算（完全一致）
int coverage = (spans->coverage * texture->alpha) >> 8;

其中 texture->alpha 在 cg_blend_texture 里已经算好（cg.c:2105）：

cg.c:2105 data.alpha 的赋值
data.alpha = (int)(state->opacity * texture->opacity * 256.0);

把两层合起来看，最终每个像素的 alpha 是：

最终 coverage = (span.coverage × (state.opacity × texture.opacity × 256)) >> 8
          = span.coverage × state.opacity × texture.opacity （数学上约去 256 与 >>8）
因子来源取值范围含义
spans->coverageRLE 光栅化0~255形状在这一像素的 AA 覆盖度
state->opacitycg_set_opacity0~1当前绘图状态的全局不透明度
texture->opacitycg_texture_set_opacity0~1纹理自身的不透明度
× 256 再 >>8整数定点技巧—用整数乘法和移位近似浮点乘法，避免每像素浮点
为什么先乘 256 再右移 8
opacity ∈ [0,1] 是浮点。若直接 coverage * opacity 就是浮点乘。libcg 把两个 opacity 相乘后先放大 256 倍转成定点，再与 coverage（本身就是 0~255）相乘，最后 >>8 除回 256。整体等价于 coverage × op1 × op2，但全程用整数，适合没有 FPU 的 MCU。
实验台对应：页面里 ca = Math.floor(sp.cov * opacity)。因为实验台只暴露一个总 opacity（把 state->opacity 与 texture->opacity 合并成一个），所以 ca = coverage × opacity 与 C 的 coverage>>8 结果一致（当 coverage 是 0~255 整数时）。

合成算子：cg_comp_map 的 4 种 operator

采样拿到纹理像素后，是怎么和目标已画内容混合的？

采样函数最后都调用 func = cg_comp_map[op] 得到的函数指针。四种 operator 定义在 cg.h:86-91：

cg.h:86-91 enum cg_operator_t
enum cg_operator_t {
	CG_OPERATOR_SRC       = 0,  // r = s*ca + d*cia
	CG_OPERATOR_SRC_OVER  = 1,  // r = (s + d*sia)*ca + d*cia
	CG_OPERATOR_DST_IN    = 2,  // r = d*sa*ca + d*cia
	CG_OPERATOR_DST_OUT   = 3,  // r = d*sia*ca + d*cia
};
cg.c:1722-1727 cg_comp_map（纹理采样用的函数表）
static const cg_comp_function_t cg_comp_map[] = {
	cg_comp_source,           // SRC
	cg_comp_source_over,      // SRC_OVER
	cg_comp_destination_in,   // DST_IN
	cg_comp_destination_out,  // DST_OUT
};

先记住一个重要前提：libcg 内部所有像素都是预乘 alpha（premultiplied，R/G/B 已乘过 alpha）。这是理解下面公式的关键。四个函数里最常用的是 cg_comp_source_over：

cg.c:1644-1671 __cg_comp_source_over
static void __cg_comp_source_over(uint32_t * dst, int len, uint32_t * src, uint32_t alpha)
{
	uint32_t s, sia;
	if(alpha == 255)
	{
		for(int i = 0; i < len; i++)
		{
			s = src[i];
			if(s >= 0xff000000)      // 完全不透明源
				dst[i] = s;
			else if(s != 0)
			{
				sia = CG_ALPHA(~s);          // 1 - sa（源的反 alpha）
				dst[i] = s + CG_BYTE_MUL(dst[i], sia);
			}
		}
	}
	else
	{
		for(int i = 0; i < len; i++)
		{
			s = CG_BYTE_MUL(src[i], alpha); // 先把源乘上 coverage
			sia = CG_ALPHA(~s);
			dst[i] = s + CG_BYTE_MUL(dst[i], sia);
		}
	}
}

四个算子的语义（s=源即纹理像素，d=目标已画内容，ca=coverage）：

operator效果公式（预乘域）
SRC直接覆盖，src 与 dst 按 coverage 线性插值r = s·ca + d·(1-ca)
SRC_OVER源盖在目标之上（默认、最常用）r = (s + d·(1-sa))·ca + d·(1-ca)
DST_IN保留目标中「被源 alpha 覆盖」的部分（用源当蒙版）r = d·sa·ca + d·(1-ca)
DST_OUT保留目标中「源 alpha 之外」的部分（反蒙版）r = d·(1-sa)·ca + d·(1-ca)
预乘 alpha 为什么重要
普通（straight）像素的 RGB 不含透明度信息，SRC_OVER 要做 src.rgb*sa + dst.rgb*(1-sa) 的三次乘法。而预乘像素的 RGB 已经是 rgb*sa，于是 SRC_OVER 直接变成 s + d*(1-sa)，省一次乘、且数值更稳。实验台里的 blendOne() 正是先把源转成预乘（round(rgb*sa/255)）再按这些公式混合。
DST_IN / DST_OUT 的用途
这两个不常用，但很有用：DST_IN 相当于「用图片的 alpha 通道当蒙版，只保留目标中图片不透明的部分」；DST_OUT 相反，是「把目标中图片覆盖的部分抠掉」。它们常配合 clip/mask 做合成。你可以在实验台把 operator 切到它们，观察 mask 如何被用作蒙版。
