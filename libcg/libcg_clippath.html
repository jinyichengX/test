libcg clippath 直觉：一张镂空模板

clippath 不是画出来的颜色，而是一张已经剪好的镂空模板。之后你画的每一样东西（fill / stroke），都只能透过模板的洞漏出来。

INTUITION

一句话：clippath 是一层「存起来的形状」

普通绘制是把形状填上颜色；而 clip 是把形状存起来当约束。存下来之后，它不产生任何像素，只决定「后面的东西能画在哪」。

cg.h:177-186 · struct cg_state_tclippath 住在「绘制状态」里，不在 surface 数据里
struct cg_state_t {
    struct cg_rle_t * clippath;   /* 已经光栅化好的裁剪模板（RLE） */
    struct cg_paint_t  paint;
    struct cg_matrix_t matrix;
    ...
};
为什么是「模板」而不是「区域」
它存的是 cg_rle_t——也就是光栅化之后的逐行 span（run-length）。每个 span 带一个 coverage（0~255）。所以它不是简单的 0/1 二值区域，而是带抗锯齿边缘的形状。这一点在 ④ 会展开。
ANALOGY

三个直觉类比

同一个概念，用三种熟悉的东西去套，挑一个最能记住的。

剪纸

剪纸 + 喷漆

先在纸板上剪出一个洞（clip），再往整张纸喷漆（fill）。漆只会从洞里喷过去，洞外被纸板挡住。

蒙版

图层蒙版

clippath 相当于 Photoshop 里的图层蒙版：它自己不显示颜色，只决定后续图层「哪些像素可见、可见多少」。

印章

镂空印章

clippath 是一个印章的镂空形状。之后不管你怎么盖章，颜色都只能落在印章的轮廓之内。

把「裁剪」和「画布」分开想
直觉上最容易犯的错，是以为「裁剪」是画布（surface）的属性。libcg 里它不是——它是绘制状态的属性（cg_state_t.clippath），跟你这几次调用 clip()/fill() 的上下文有关，跟 surface 的像素数据无关。
SAME RASTERIZER

clip 和 fill 是「同一套光栅化，两个出口」

关键直觉：clip 和 fill 走的是完全相同的「path → RLE」光栅化。唯一区别在最后一步——fill 把 RLE 送去 blend 填色，clip 把 RLE 存进 state->clippath。

→
rasterize光栅化成 RLE
→
clip 出口存进 state→clippath
(当模板，不填色)
path一条路径
→
rasterize光栅化成 RLE
→
fill 出口先和 clippath 求交
再 blend 填色
cg.c:2456-2470 · cg_clip_preserveclip：把 path 光栅化后「存」起来
state->clippath = cg_rle_create();
cg_rle_rasterize(ctx, state->clippath, ctx->path, ...);  // 只存，不填色
cg.c:2478-2485 · cg_fill_preservefill：光栅化后先和 clippath 求交，再 blend
cg_rle_rasterize(ctx, ctx->rle, ctx->path, ...);   // 1. 光栅化当前形状
cg_rle_clip_path(ctx->rle, state->clippath);      // 2. 与模板求交（裁剪）
cg_blend(ctx, ctx->rle);                            // 3. 只画交集部分
一句话记法：clip 是「存模板」，fill 是「先裁再画」。两者共用一个光栅化器，差别只在最后一步往哪走。
COVERAGE ×

交集是 coverage 相乘，不是「布尔与」

两个形状求交时，不是「在不在里面」的 0/1 判断，而是把两个形状的 coverage（0~255 抗锯齿覆盖率）相乘。这样交集出来的边缘依然是平滑的。

模板 coverage (A)

软边圆，边缘 coverage 从 255 渐变到 0

形状 coverage (B)

软边方块，同样有渐变边缘

结果 = A × B ÷ 255

只保留重叠区，且边缘是「两层渐变相乘」
cg.c:1045 · cg_rle_intersection交集处 coverage 直接相乘
span->coverage = CG_DIV255(a_spans->coverage * b_spans->coverage);
为什么相乘而不是取最小
相乘的物理含义是「两个遮挡都成立才透光」。模板挡一半（coverage=128）、形状挡一半（coverage=128），两者叠起来只剩 128×128÷255 ≈ 64。取 min 会得到 128，那就把「双重遮挡」错当成「单层遮挡」了。相乘才能正确叠加抗锯齿。
RLE STRUCT

RLE 结构体：coverage 这么存、这么画

coverage 不是逐像素数组，而是一串 span。下面在 JS 里编一个和 cg_span_t / cg_rle_t 等价的结构体，走一遍「形状 → 编码成 span → 从 span 画出 coverage」。

// struct cg_span_t { int x; int len; int y; unsigned char coverage; }
function span(x, len, y, coverage){ return {x:x, len:len, y:y, coverage:coverage}; }

// struct cg_rle_t { span[] spans; int x,y,w,h; }
function rle(){ return {spans:[], x:0, y:0, w:0, h:0}; }
encode → decode同行、coverage 相同的连续像素合并；画的时候逐 span 铺回去

// 画：遍历 span，把 coverage 写回对应像素
for(s of spans) for(k=0;k<s.len;k++) out[s.y][s.x+k] = s.coverage;
